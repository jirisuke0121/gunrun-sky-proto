# 見た目の追加分の重さを実機で一括計測（2026-11-20）

## なぜ測るか
実機（iPhone・画質「高精細」・描画1266×585・影あり）の `diagnostics.perf` で、1フレームの間隔が11/9〜10の約18msから11/14〜17の約24〜27msに伸びた。ゲーム処理（CPU）は約10msのまま、差はGPU待ち（`iv − cpu`が約11ms→約15ms）。
11/11〜11/12に入れた見た目（太陽グロー・輪郭線・塵・接地影・遠景）が重くなった候補だが、時期が重なっているだけで原因は確認できていない（同じ期間にほかの更新も入っている）。仕組みからの見立てでは ① 太陽グロー（`mood.js` の `Sun glow`、420mの加算スプライト、どの画質でも常時）② 輪郭線（`ink-outline.js`、静的な建物を裏向きにもう一度描く、三角形 +約8%）の順に怪しい。

## 使い方（実機）
`https://jirisuke0121.github.io/gunrun-sky-proto/bench/ab-glow-outline.html` を開くだけ。読み込み後に自動で始まり、約1分半、画面に触れずに待つ。結果は画面に出る（「結果をコピー」で貼れる）。

- iframeで `index.html` を開き、ゲームを自動で始め、見た目の5つ（太陽グロー・輪郭線・塵・接地影・遠景）を1つずつ消した条件、5つとも消した条件、参考の「描画解像度×0.75」を、現状と入れ替えながら測る。
- 1ラウンドで全条件を一巡し、順番をずらして6ラウンド。熱や時間経過の影響を、ラウンド内の対の差で相殺する。
- 60fps上限に差が隠れないよう、1フレームに K=3 回ぶん余計に描画して差を4倍にし、結果は4で割って「1回の描画あたり ms」で出す。
- 判定の目安：1ms以上＝大きい、0.3〜1ms＝小さい、それ未満＝誤差。差が±ばらつきより小さい（t<2）ときは「判定不能」。
- 画面が隠れる・タブが止まって描画タイマーが止まった区間（間隔400ms超、`?stall=`で変更）は除外して数え、無効なラウンドは落とす。有効が3ラウンド未満なら判定しない。
- 速いGPU（Mac等）では、描画命令の発行（CPU）が先に詰まってGPU差が見えない（実際、Macでは5つとも差0）。実機のiPhoneで測るのが前提。`?pr=4` のように描画倍率を上げるとGPU側が詰まる条件にできる。
- 影とアンチエイリアスは切り替えに作り直しが要るので測らない（参考の解像度×0.75が「軽量にしたときの効き」の目安）。
- ゲーム本体は変更しない。プレイ記録は送らない：iframe の `fetch` / `sendBeacon` を、ページを閉じるまで止めたままにする（返事は「保存済み」の形）。
  - **失敗の記録（2026-11-20）**：最初の版は計測後に送信を元へ戻していたため、ゲームが120秒で自然に終わったときに記録が本番へ送られ、順位対象の記録が2件（ノーマル2959点・ハード4066点、立ったまま無敵で120秒生存）入った。計測後も送信を止めたままにするよう直した。
- 調整：`?auto=0`（手動開始）`&slice=1200&rounds=6&k=3&settle=300&stall=400&pr=`。

## 確認範囲
- ヘッドレスChrome（ソフトウェア描画）で、自動開始から結果表示まで通ること・プレイ記録のPOSTが0件であることを確認。この環境の数値はGPUの代わりにならない（フレームが遅く、有効判定を満たさない）。
- MacのGPU（Claudeデスクトップのブラウザ・844×390・描画倍率2・影あり）：グロー−0.03ms、輪郭線−0.02ms（±0.1〜0.17ms）で誤差。ただしCPU側が詰まる条件で、GPUの差は見えていない。
- iPhoneの数値は未取得。結果が出たら、効果が大きいものだけ除去（または画質「軽量」で切る）する。
