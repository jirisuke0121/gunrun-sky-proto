# 持続する風音の調整 — 2026-11-07

報告: 入門からイージーへ自動で進むと、大きいノイズがプレイ中ずっと続く。

通常開始と入門後の自動開始の各音源をWeb Audioの実出力で分離測定した。今回のデスクトップChromium計測では、両入口の主音量は0.7で同じだった。移動時の風音がBGMの約3倍、高速空中移動では約14倍のRMSとなり、背景の持続音として過大だった。これが実機の報告音と完全に一致するかは未確認。

| 場面 | 修正前の風RMS（主音量を通す前） | 修正後の風RMS目安 |
| --- | ---: | ---: |
| 地上6m/s | 0.044〜0.046 | 約0.009（約14dB低下） |
| 空中6m/s | 約0.065 | 約0.012 |
| 高速空中20m/s | 約0.20 | 約0.018（約21dB低下） |

風の速度係数を抑え、風音のゲインに0.12の上限を設ける。ユーザーの主音量、警告・銃・足音、BGMの音量や音色は変えない。

また、入門の停止は物理更新より前で止めるため、従来は直前の風音が残り続けることがあった。音声更新側で停止を認識し、風・フック・ジップの持続音だけをフェードアウトする。実際の移動状態の履歴は維持し、停止・再開だけで接続／解除音を重ねない。

`bench/ambient-wind-browser.cjs` は両マップ × 通常／入門終了の4条件で、ネイティブのAudioContext、風のループとフィルター、実際のゲーム更新を通した出力を測る。入門の実技は既存の完走試験に任せ、この試験では本番のfinish処理とページ遷移を使ってイージー自動開始を確認する。修正前は地上走行のRMSが許容値を超えて失敗した。停止時のフェードと主音量の保持も検証する。

実機iPhoneでの音色・音割れ・他アプリとの干渉は、このブラウザ計測では確認できない。
