# 自動追従の連続操作を修正して通常の簡単操作へ適用

## 対象と完了条件

先行比較 `AUTO_FOLLOW_ONLY_2026-11-08.md` では、右の視点操作だけを外しても、西廊下で曲がった後の上入力が元の向きへ戻り壁に当たった。今回はこの移動入力を直し、通常開始・入門・リトライでも手動視点なしの追従を使う。既存PCのWASD＋マウス、地形、敵、戦闘、速度、ジャンプ、ランキング規則は変えない。

1. 左右へ倒して曲がり、同じ指を上へ戻すと新しい進行方向を保つ。戻す途中も元の向きへ折り返さず、保持した指で勝手に旋回し続けない。次の左右操作を続けられる。
2. 同じ指で下へ倒すと後退し、上へ戻すと前進を再開する。後退だけで視点を半回転させない。中立・解放・キャンセル・フォーカス切替・特殊動作への出入りを保持する。
3. 右側に指を置いても追従を止めず、右ドラッグは視点を回さない。二本指ジャンプ・空中修正・PCの手動視点を保つ。
4. 両マップで通常開始・日英の案内・リトライ・入門復帰を確認し、GitHubの検証を通してから公開する。公開先のファイルと実動作も確認する。

## 入力の扱い

`follow-camera.js` は、横へ倒す間に増えた角度で進行方向を変える。上方向へ指を戻す間は、決めた進行方向を継続する。入力角の変化がスティック半径56px上の2px以内なら新しい旋回として受け付けない。保持中の微小な揺れで角度を積み増さないための幅で、1pxの揺れを10秒続ける検査を設けた。半径だけの変化は速度だけに反映する。

下／上の中央の範囲に入ると、同じ指で後退／前進を切り替える。はしご等の特殊動作から保持したまま出た場合は、その動作の退出方向を優先する。カメラの回転は入力の保持方向へ戻さず、進行方向を追従する。立ち止まって視点を回す操作は不要。

通常の簡単操作は手動視点なし。明示的な `cameraTrial=follow-legacy` だけが比較用の旧入力・手動見回しを使う。`camera=before` は従来どおり手動視点。過去の固定カメラ保存フラグの復元と入門への固定カメラ強制は撤去する。`cameraTrial=fixed/hybrid` を明示した比較入口は残す。比較URLは記録を送信しないが、通常URLの記録は維持する。

## 再現と検証

`bench/follow-camera.test.cjs` に左右の連続曲がり、指を1回／30回に分けて戻す、同じ指の後退・前進・反対方向への曲がり、微小な揺れ、半径変化を追加した。保存した変更前ソースでは「上へ戻すと曲がった先を進む」検査が失敗し、修正後は合格する。

`bench/auto-follow-browser.cjs` はChrome DevTools Protocolの実タッチイベントをゲームへ届け、両マップの実地形で旧版と修正版を比較する。物理スマホの手操作ではない。旧市街の西入口 `(-15.5, .001, 0)` で、上45フレーム→左40→上35→下30を、指を離さず実行する。別試行では左から上への戻りを30分割する。ゲーム時計は60Hz、描画は6フレームごと。開始後に位置を補正しない。

西廊下の上入力35フレームで、旧版は元の向きへ約90度折り返し、移動約0.25mで壁に止まる。修正版は曲がった方向を保ち約3.5m進む。ゆっくり指を戻す場合も同じ方向へ継続する。下入力で体の向きを変えず約0.86m戻る。通常ゾンビ2体を開始時だけ後方に配置し、無敵を解除した2.5秒の同じ経路では、敵が実際に動き、ライフを失わず旧停止地点の先まで進む。

証拠は `browser-evidence/auto-follow-release/`。固定カメラや切り欠きへの置き換えは使っていない。西廊下では既存の衝突回避により視点が人物に近づき人物が非表示になる。今回の確認は進路と入力の不一致を対象とし、狭い場所の見え方全体の解決を意味しない。直近の写真の座標の厳密同定、物理iPhoneの操作感、初見利用者の理解、長時間のハード逃走は未確認。
