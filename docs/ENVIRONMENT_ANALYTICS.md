# 国・端末環境、任意期間、描画倍率（2026-11-02）

## 範囲

本人専用の管理画面に、国別の利用件数、ブラウザ申告の端末情報、任意の日付範囲を追加する。GPU情報の収集やNIGHTLINEの全運用機能は含めない。プレイヤー一覧は後続の [プレイヤー管理仕様](PLAYER_OWNER_CONSOLE.md) で追加し、同じブラウザの匿名IDごとの利用状況を確認できる。

## 計測

- 国はゲームから既存Workerへ直接届いた `request.cf.country` から取得する。本文や任意のHTTPヘッダーは国の情報源にしない。管理画面の中継サーバーの国で置き換えない。
- OS・ブラウザとバージョン、任意のAndroid機種名、利用可能な論理コア数、概算RAM、画面サイズ、端末DPRを収集する。iPhoneの型番やCPU型番、正確な搭載RAMは推測しない。端末情報はブラウザの申告であり、実機の確定スペックや性能スコアではない。
- 端末情報はページごとのセッションIDに結び付ける。後続のプレイヤー管理では既存の `gunrun-pid` と設定済みの呼び名を共有する。新規の追跡用ID、メール、GPU文字列、UA全文、生IP、GPSは追加しない。国は最初に受信できた値、端末情報は同じセッションの最新の申告を使う。各プレイの描画倍率・バッファ寸法・影は終了時の性能記録に保存する。
- 既存の記録送信オフ、入門・練習・開発用の送信除外を維持する。機種名の取得は非同期で、開始や計測の送信を待たせない。
- 管理画面の国・環境別件数はセッション／プレイ／FPS計測の件数。人の数ではない。FPSがない記録を0に置き換えず、平均の母数を表示する。
- 過去に収集していない国・端末情報は「不明」。終了通知がない場合に、離脱や原因を確定したと表示しない。

## 任意期間

APIの `from=YYYY-MM-DD&to=YYYY-MM-DD` は日本時間。開始日00:00以上、終了日の翌日00:00未満を対象にする。日付は両方必須で、存在しない日・逆順は400。開始前の過去期間や未来の空期間も指定できる。従来の `days=1|7|30` は互換のまま残す。

すべてのパネルに同じ受信日時の条件を使う。イベント単位の集計なので、日付をまたぐプレイの開始と終了が別期間に入ることがある。完走率・個人別の離脱率としては表示しない。2期間の並列比較や因果推定は含めない。

## 描画設定

| 選択 | 3Dピクセル／CSSピクセル | 影 |
| --- | --- | --- |
| 高精細（従来） | 従来の端末DPR上限2とrenderScale | 従来の影 |
| 標準 | 1.0倍固定 | 1024の影 |
| 軽量 | 0.75倍固定 | なし |
| 最軽量 | 0.5倍固定 | なし |

高精細が既定で、保存済みの選択を引き継ぐ。固定倍率では従来のrenderScaleと掛け合わせない。プレイ中の手動変更と画面回転・リサイズでも、そのプレイの倍率を変えない。影の扱いも選択したプリセットに従って次回から適用する。物理・入力・敵数・得点や描画回数の上限は変更しない。

影はNIGHTLINE方式への置き換えを必須にしない。ローカルの同一シーン・カメラ・倍率の比較を `bench/foundation-shadow-browser.cjs` に用意する。結果はソフトウェア描画の処理時間で、プレイヤーFPSやiPhone実機の結果とは区別する。

## 公開・運用

1. `server/telemetry-environment-schema.sql` を本番D1へ適用する。新しい補助テーブルの追加のみで、既存記録・順位・ゴーストを変更しない。再適用できる。
2. Workerを更新する。公開のルート情報で `environmentTelemetry:1` と `customDateRange:1` を確認する。
3. 管理画面のSitesを既存の本人専用アクセスのまま更新し、ゲームを更新する。管理画面は旧データの欠測にも対応する。

Sitesの接続キーや本人専用アクセスは従来どおり。[認証の運用](OWNER_LOGIN.md)。旧トークン画面にも同じ集計欄を用意する。

検証：`node --test bench/foundation.test.cjs bench/foundation-environment.test.cjs`、既存の記録・順位・ゴースト・起動テスト、`bench/foundation-browser.cjs`。管理画面のSites側では `node --test test/owner.test.mjs` と `node test/browser.cjs` で、日付・絞り込み・欠測・390px幅・接続失敗・ログイン切れを確認する。本番検証では架空のプレイを追加しない。

## 影のローカル比較

Mac上のChrome／SwiftShader、2560×1440（2倍）、両マップ開始地点、同じシーン・カメラで24サンプルずつ測定。方向光の影は1個・2048×2048。影あり／なしの描画処理時間中央値は旧市街2.2／1.8ms、渓谷1.1／0.9ms。これはソフトウェア描画でGPU完了を待った処理時間であり、通常プレイのFPS・iPhone実機の改善値ではない。この結果だけで高精細の影を一律に削除しない。軽量・最軽量では影を省略する。
