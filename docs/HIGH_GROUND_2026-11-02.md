# 写真の北側5m壁に追手が到達しない問題

## 過去の確認範囲

PR #83 は旧市街の12m壁での登攀を確認していた。PR本文には添付写真と完全に同じ座標、全登攀経路、iPhone実機は未確認と記載されている。PR #84 の両マップの通常追跡確認も、この写真の足場への到達を証明していない。

今回の写真は、東塔とオレンジの階段を南に見る北側の壁と構図を照合した。壁の範囲は x=23..36、z=-27.4..-25.2、天面5m。中央の確認座標は (30,5.003,-26.3)。写真の正確な立ち位置は不明だが、同じ壁の中央・両端で確認した。

## 原因と変更

- この壁は `mono` で通常NAVに天面がなく、追跡フィールドがプレイヤーの以前のノードを使っていた。敵を壁の直下に置けば登れるが、少し離れた位置からは以前の場所へ向かい、登攀の開始地点へ来ない。
- 地形と体の通過・足元の支持を確認した壁下の既存ノードを、一時的な複数の経路目標にする。壁や柱を共有NAVに追加せず、既存の4秒待機と低速登攀へ接続する。回り込みの別フィールドによる古い目標への誘導も防ぐ。
- 壁下の足場で待機している間に、中央の隙間へ斜めに歩き出さないようにする。足元の支持、被弾、閃光、分身、プレイヤーの移動などの条件を確認する。
- 塔側から降りる敵には別の停滞もあった。足の高さに10cmを足してノードを選ぶと、20cm上の階段ノードを選ぶケースがあった。敵のノード選択は足の実際の高さに合わせる。
- NAVの細い判定は通るがゾンビの体は通れない降下リンクは、既存の20秒間の経路閉塞扱いにして経路フィールドを更新する。実際の降下は従来どおり体の掃引と着地点の支持を検査する。

## 再現と確認

基準は `8b1eda4`。修正前後で同じ地形・モデルを読み込み、開始時に配置した後は実ゲームの物理・AI時計を固定刻みで進めた。移動中の座標補正は行わない。実機の手操作確認とは異なる。

- 修正前：壁の中央にプレイヤー、南東の既存足場に敵を置き、40秒後も被弾なし。敵は以前の場所へ移動。
- 修正後：PCとタッチ表示それぞれで、南東・南西・下段の回り込み個体・壁右端・壁左端・塔からの降下の6条件すべてで登攀完了と実際のライフ減少を確認。南側と下段は約12.3〜17.1秒、塔側は約37.9秒で被弾。登攀中の地形侵入は0。
- 通常出現を残したハード：乱数種20261102/03/04、射撃なし・移動入力なし、PCとタッチ表示の各3回。初被弾約25.8〜30.1秒、ライフ0・終了は約30.3〜34.5秒。全登攀中の地形侵入は0。これは無敵地点の再現条件に対する確認で、難易度全体の評価ではない。
- 両マップ×PC/タッチの既存追跡ブラウザ確認が通過。追跡・遮蔽・分身終了後の復帰・閃光などを確認。
- 既存パルクール確認もPC/タッチの双方で通過。各30通りの進入・解放、下段への落下から階段と地上への復帰、各3種の追手が降りて再接近する経路を確認。
- 単体確認：壁下目標の生成とキャッシュ・足元支持・無効地形・通常床、NAV更新・閉塞・キャッシュ、降下開始、階段の床選択。両HTMLの全インラインJS構文と差分検査を通過。

再現用: `bench/zombie-wall-approach-browser.cjs`。`WALL_APPROACH_BASELINE=1` は基準 `8b1eda4` の変更前ソースを読み込む。通常実行は現在の作業コピーを検証する。`RUNNING_QA_URL` でローカル配信先、`WALL_APPROACH_OUT` で保存先を指定できる。

再発確認を継続するため、階段の床選択・壁下目標・NAV更新と写真の壁への実到達確認を既存のRunning browser checksへ追加した。

公開状況は対応PRとGitHub Pagesのデプロイ結果で確認する。iPhone実機と全マップの全高台は未確認。
