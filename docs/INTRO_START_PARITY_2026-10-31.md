# 入門・本番の開始と表示を揃える（2026-10-31）

公開版7a60116に対する「入門が三人称にならず簡易銃」「本番ボタンを押しても開始しない」の指摘へ対応する。

## 原因と変更

入門は人物・銃の読み込みを待たずgame.br()を直接呼んでいた。本番はボタンが有効に見えても、人物ロード中のcaptureハンドラーで開始を止めていた。ローカルで人物GLB・HGを止め、両方の状態を再現した。

start-readiness.jsで入門・本番の両ボタンを管理する。人物、HG、ゲーム拡張、設定・カメラ、ゾンビの準備が揃ってから有効化する。準備中は対象をボタンと直近の説明に表示し、失敗時は再読み込みを案内する。ゾンビの読み込み処理がボタンを途中で有効化しないよう、準備状態を公開して同じ管理処理に委ねる。

入門は通常Startのクリック経路を使い、開始前確認・音声等のリスナーを共有する。入門フラグは同期開始中だけに限定。開始直後の連打で別の実行を作り直さないよう、menu以外の開始も防ぐ。難易度・ライフ・記録版・Worker・Vキーの切替・プレイヤー設定は変更しない。

## 要件と証拠

| 要件 | 確認 |
| --- | --- |
| 人物・銃が本番と違わない | 遅延させた修正前の早期開始を再現。修正後は両マップで準備までmenuを維持し、解放後はUnityアニメーションの三人称。渓谷の保持武器にMeshy HG mobile LOD、音声running、入門ライフ∞を確認 |
| 本番が開始できる | 旧市街で旧版の有効に見えるボタンがmenuのままになることを再現。修正後は準備中表示＋disabled、準備後の実ボタン1クリックでplay・三人称・HG・ライフ5を確認 |
| 復帰でデグレしない | 手動で一時停止・再開・再挑戦を確認。開始の回帰ブラウザでは両マップ×PC/タッチの本番、メニュー、プレイ前設定、入門、入門再挑戦、通常復帰を確認する |
| 失敗が無反応に見えない | 単体確認でモデル・モジュールの失敗、再読み込み、準備完了後の回復。ブラウザ確認ではHG404→再読み込み→本番開始を扱う |
| 記録を壊さない | 既存のrecord-integrity・ranked-spots・ranked-ghost・audio-recoveryのローカル処理テスト成功。新しいブラウザ確認は入門記録なしと外部POSTなしも確認する |

新設したbench/start-readiness.test.cjsは、読み込み順が異なる場合のボタン状態、disabledを迂回したクリック、連打、練習場ラベル、失敗・再読み込みを検証する。bench/start-readiness-browser.cjsは実アセット要求を順に解放して状態と実画面・操作を確認し、既存ranked-spotsワークフローで実行する。既存の全体CIも継続する。

Macのブラウザで再現・操作しており、報告元のiPhone実機での再確認は未実施。CI、公開の最終状態、配信内容の一致はPRとPagesで別途確認する。証拠は作業用verification/intro-start-parityへ保存。
