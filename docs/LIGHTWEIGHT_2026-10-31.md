# 軽量モードと人物アニメーションの追加軽量化（2026-10-31）

軽量モードの描画倍率上限を0.8から0.7へ下げ、人物の変形アニメーションで毎回作り直していた名前と番号の対応表を再利用する。FPSの最終改善率は未確定。ユーザー指定により、今回は実装と動作確認までを対象とする。

## 変更

- CSS 1200×762・DPR2では、軽量の3D描画サイズが960×609から840×533へ変わる。画素数は584640から447720で約23.42%減。文字・操作ボタン・画面上のサイズは維持する。影なしは継続し、標準と高画質の設定は維持する。
- 人物7メッシュの256項目ずつ、計1792組の変形名と配列番号をキャッシュする。従来はアニメーション更新ごとに`Object.entries`の外側7配列と1792組の配列を作っていた。更新時は保存した対応表を順番通りに使う。辞書そのものか変形配列の長さが変わった場合は再作成する。
- 背景結合、照準の回転共有・行列再利用、生存中と死体を合わせた6体枠は継続する。今回の変更で人数・体力・速度・衝突・射撃・記録ルールは変更しない。体力はEasy→Ultraで4/6/7/8/9/10。
- 比較ページはFPS比較とCPU内訳計測を分け、CPU内訳は既定でオフにする。前面状態と照準状態、実際の人物メッシュも記録する。接近の反復を0.6秒にし、全6体が地形に隠れず映る条件を確認する。ゲームの追跡処理は変更しない。

## 動作確認

両マップで静止・走行・歩行・ジャンプ・スライド・通常射撃・上向き射撃・下向き射撃の16場面を実ゲームから記録した。軽量0.7でも、変更前保存版と人物7メッシュの頂点・法線ハッシュ、モーフ値、プレイヤーの位置・接地・状態、銃口と射線、命中結果が一致した。対応表は7メッシュで7回だけ作られ、同じモデルで繰り返す更新中は増えなかった。旧市街の扉の開閉・衝突切り替えも確認した。

実際のホーム画面で軽量・標準・高画質を選び、同じCSS 1200×762のまま描画サイズが840×533、1200×762、2400×1524へ変わることを確認した。高画質を選んで渓谷へ移動しても高画質を維持し、軽量へ戻して旧市街へ移動しても軽量0.7を維持した。確認用画面では初期値リセット、設定側の選択との同期、影のオフ／オンも確認した。実ページの設定は元の軽量へ戻している。

構文・差分を確認した。自動テストは追加・手動実行していない。PR更新で起動する既存CIの結果は、上の実行確認と区別する。

## FPS比較の扱い

Macのロック解除後、Chrome・M1 Pro・同じ視点・6体で比較を試みた。詳細CPU計測あり／なし、同じタブの連用／新規タブ、前面状態を区別して記録したが、変更前を測り直した場合にも大きな変動があった。倍率0.7で旧市街の固定場面が約64FPSになる試行と、低い値になる試行の両方がある。これを安定60FPSや確定した改善率として扱わない。

接近中に1体が地形に隠れた試行は、全6体表示の条件を満たさないため無効として残している。比較条件を変更した試行も混ぜない。途中の低い結果を削除して良い結果だけで集計していない。最終的にユーザーが「今回は実装と動作確認まで進める」を選択したため、FPS比較の確定は今回の範囲外とする。

描画命令数・画素数・対応表生成の削減は別の指標であり、それらの削減率を合算したり、そのままFPS改善率へ置き換えたりしない。以前の高画質→軽量約13→52FPSという結果も、当時の画質と条件の結果として分ける。

[数値と照合結果JSON](lightweight-runtime-20261031.json)に、最終ソースのSHA-256、16場面の判定、画質切り替え、保存、各予備試行の区分を保存した。元のフレームと画像は作業フォルダの`verification/crowd/fps-unlocked-20261031/`、`verification/crowd/final-runtime-20261031/`に保存している。

比較ページの変更前選択には、同じ人数・体力とmain `c6544cc`の追跡・探索を含むローカル保存版を使う。作業ブランチを取得した環境で次のように作成できる。生成されるtreeは`82ce74cd8018eee78d1664471f8d53c67faba8b8`。変更前の軽量上限は0.8、現在は0.7なので、画質を含む実装全体の比較と同画質での処理比較を区別する。
