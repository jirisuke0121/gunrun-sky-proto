# 経路検索の整理と軽量化（2026-11-08）

「たまに重くなる」の原因を、実プレイに近い条件で測って特定し、見た目の動きを変えない範囲で軽くした記録。

## 経路検索のしくみ（旧市街・渓谷とも同じ）

- 道は「ノード（立てる地点）」と「エッジ（歩き・登り・ジャンプ・はしご・飛び降り）」のグラフ。旧市街はノード4,148・エッジ38,713、渓谷はノード4,706・エッジ102,551（1ノードから平均22本）。
- プレイヤーのノードを起点に、全ノードからプレイヤーまでの最短コストを `so`（ダイクストラ法）で一括計算して `Vn`（通常）と `Ld`（飛び降りを使う落下型）に入れる。打ち切りは400で、実質マップ全体。
- 作り直しの判定は `go`（0.35秒おき）。プレイヤーの0.7秒先のノード、ドア、通行妨害、屋内の解放、はしごの状態が前回と同じなら何もしない。
- 各ゾンビは0.25秒おきに `pickEdge` で、出ているエッジのうち「エッジのコスト＋行き先の距離」が最小のものへ進む。値を読むだけなので軽い。

## 測定（headless Chrome・同一乱数・ハード・自動で走るプレイヤー・ゾンビ8体）

- 旧市街・渓谷の各60〜150秒を、1フレームのCPU時間（物理・AI・人物表示）で測定。CPUの取り合いを避けるため1つずつ実行。
- 重いフレーム（33ms超）の大半は、`go` が起こす距離マップの再計算（`playerField`）。移動で目的のノードが変わるたびに、全マップの探索が2回走る。旧市街は約1回/秒、渓谷は約4回/秒。1回は約10〜12ms（最大28ms）、2回が同じフレームに重なると最大60ms。
- 平常時の最大の内訳は、プレイヤー人物の武器の向き計算（`human-view`→`human-aim`）で約3.3〜3.6ms/フレーム。経路探索は平均0.5〜0.8ms。
- 別件：旧市街の西端で詰まったゾンビの更新が、約1.5秒おきに100〜270msかかる現象が、一部の計測で出た（120秒で29回）。他の8回では出ず、原因の関数は未特定。

## 入れた変更（距離配列は変わらない）

1. **待ち行列を配列だけに**：探索のたびに作っていた `[距離, ノード]` の小配列をやめ、型付き配列で持つ。
2. **歩き・登り・乗り越えの辺コストを表に**：状態キー（ドア・通行妨害・屋内・はしご）が同じ間は、辺ごとのコストを再利用。ジャンプ・飛び降り（kind 6/7）は時間で変わるので毎回計算。
3. **2枚目（落下型）は次のフレームへ**：同じフレームに2回の探索が重ならないようにした。開始直後だけ両方を即時に作る。開始時に次フレーム待ちが残っていれば取り消す。

## 効果（同じ乱数3通り×各60秒で前後比較。headless Chrome、iPhoneではない）

| 1フレームの合計CPU（3乱数の平均） | 旧市街 前→後 | 渓谷 前→後 |
|---|---|---|
| p99 | 30.8 → 17.3 ms | 30.5 → 17.9 ms |
| p95 | 12.7 → 10.9 ms | 15.2 → 11.3 ms |
| 経路探索の1フレームあたり平均 | 0.63 → 0.36 ms | 1.06 → 0.73 ms |
| 経路探索が1フレームで最大 | 56.8 → 24.4 ms | 52.1 → 40.2 ms |

- 探索1回の時間は、実マップの実コストで、旧市街 3.9→2.4ms、渓谷 5.2→3.2ms（約40%減）。
- 追跡の質：最寄りゾンビまでの距離の平均は 2.19→2.17 m（旧市街）、1.23→1.26 m（渓谷）で変わらない。`bench/zombie-routing-browser.cjs` の「渓谷 地上→中段」の移動距離も 13.9→14.0 m。人が遊んだ体感は未確認。

## 試して取り下げた案：再作成の間隔（0.7秒）

- 目的のノードが動いただけのときは、前回から0.6秒以内なら再作成を見送る案。探索回数を減らせる想定で入れた。
- `bench/zombie-routing-browser.cjs` で、渓谷「地上→中段」のゾンビの移動距離が 13.9 → 76 m に伸び、失敗した。古い目的地のまま選んだ遠回りの経路を、そのまま続けてしまうことがある。
- 間隔を外すと 14.0 m に戻ったため取り下げた。「見た目の挙動を変えない」条件に合わない。

## 入れなかった案と理由

- **ゾンビの位置までで探索を打ち切る**：`Vn` は出現地点の選択（13〜60 m先に届くか）、見失い用の `LF` コピー、同時数の圧力計算などが遠いノードも読む。打ち切ると挙動が変わるため見送り。
- **落下型の距離マップを必要な時だけ作る**：`dropperShare` が0.5で、ほぼ常に落下型が1体はいるため効果が小さい。代わりに「次のフレームに回す」で山を低くした。
- **回り込み役の探索の共有**：旧市街は回り込み役1回あたり約10ms、90秒で約20〜120回。渓谷はすでに状態ごとの共有（`flankPath`）がある。効果が小さく、挙動が変わるため見送り。

## 確認

- `node bench/path-search-memo-browser.cjs`：実マップ・実コストで、素朴な全探索と距離配列が一致（メモあり・なし、ドア切替、複数起点、初期コスト付き。2マップ合計85万要素で差0）。CIの `running-browser.yml` に追加。
- `node bench/nav-field-refresh.test.cjs`：次フレーム更新と、再開時の取り消しを追加。
- `node bench/path-distance-rounding.test.cjs`、ゾンビ系の単体・ブラウザ、ほか関連テスト（README の同日の節を参照）。
- 既存の `bench/flank-path-cache.test.cjs` は、変更前から `window is not defined` で失敗する（今回の変更とは無関係）。
