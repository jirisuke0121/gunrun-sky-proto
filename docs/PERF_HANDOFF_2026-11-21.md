# 重さの調査：引き継ぎメモ（2026-11-21）

次に重さ・見た目を扱うAIは、これを読んでから始める。ここに書いた調査は繰り返さない。

## 本人の方針（11/20）
- 今は大きな性能改修の節目ではない。CrazyGames・Y8への提出と、マップの見た目の改善を控えている。
- 決めたいのは **スマホの既定画質**。それを決めてから、見た目の改善を負荷の予算内で進め、提出する。

## 決定（11/21）
- 実機で `?q=balanced`（1.0倍・影あり）と `?q=performance`（0.75倍・影なし）を4周ずつ測った。解像度は効かず、影を切ると各周2〜3.5ms速い。
- **スマホの既定を「高精細・影なし」（`phone`）にした。** PCは影ありの高精細のまま。「重くなったら自動で下げる」案は、解像度が効かないと分かったので撤回。
- テクスチャが周ごとに増えるのは、倒したゾンビの骨のデータ（16×16の浮動小数テクスチャ、1枚約4KB）が片づかないため。172枚でも約0.6MBで重さの原因ではない（未修正、後回し）。

## まだ分かっていないこと
- 熱かページ内の溜まりか：`bench/soak-trajectory.html?reload=1` は未計測（ただし上の証拠からは熱が本命）。
- 画質を下げると周の悪化が止まるか：`?q=balanced`（1.0倍・影1024）の4周は未計測。**これが既定画質を決める一番の材料**。
- `bench/ab-look-classic.html`・`ab-look-bisect.html`・`ab-quality.html` の実機結果は、このメモの時点で受け取っていない。

## 次の一手（提案）
1. 冷えた状態で `bench/soak-trajectory.html?q=balanced` を4周。判断基準：4周めが1周めの+2ms以内、30fps未満5%未満なら、スマホの既定を「標準」にする案を詰める。
2. 基準を満たさないときだけ `?reload=1` と `?q=performance` を測る。
3. 既定を変えるなら、2回目以降の悪化も軽量化案内で拾えるようにするか（上の `markQualityChecked` の扱い）を一緒に決める。
4. 見た目の改善は、決めた既定画質の上で。候補（`docs/MOOD_2026-11-12.md` の続き）：朝焼けの白っぽさ（環境光1.95・露出1.4が強い、数値だけ）、人物の色味を光に合わせる（`look-pass.js` に人物の処理なし）、霧の色の層、床の目地・屋根の瓦。
