# 経路停止の広域点検 — 2026-11-06

## 完了条件と修正範囲

| 確認する問題 | 修正・判定 |
| --- | --- |
| 屋上の下の壁・途中の張り出しを見落とす | 屋根板だけでなく実際の支持壁から登る候補を調べる。接する面と途中の棚も索引に含める |
| 細い縁では中央に着地できず停止する | 実モーターと同じ足の接地範囲を使う。中央と縁の候補を身体全体で掃引して確認する |
| NAVのない足場に移ると古い目標に向かう | 支持された歩行・跳び移り・下降の出発ノードを一時目標にする。残りの移動時間を重みに含め、元の目標はコスト0のまま保つ |
| 同じ場所を周回する／段差で接地が一瞬切れる | 距離または残りの経路コストが改善した時だけ進捗扱いする。一時的な空中判定では探索履歴を消さない |
| 探索中に動いたため、開始位置が古くなる | 登りを開始する直前に、現在位置から接続を組み直す |
| 初回の経路選択前に縁から歩き出す | 出発ノードが未取得の敵は、最初の移動前に経路を選ぶ |
| 入口の境界で攻撃が毎フレーム中断される | 人間の入室判定と立入禁止範囲の境界を揃え、元から届く近接攻撃の予備動作を保つ |
| 群れの着地点と登り・下降の探索が競合する | 空いている横の着地点も予約候補にする。下降の実行・探索中は古い登り探索を再開しない。身体で塞がれた有効な登り口は混雑待ちとして探索を区切り、他の追手へ探索枠を渡す |

対象は `zombie-climb.js`、`zombie-descent.js`、`zombie-routing.js`、`indoor-access.js` と両HTMLの経路コスト初期化。キャッシュ版も更新。

敵の速度、最大ジャンプ距離4.3m・上昇1.2mなどの既存上限、難易度ごとの跳び移り失敗、PCの手動移動・視点操作は維持する。新しい移動も実地形の支持・身体の通過・立入権限・着地後の経路を確認する。被弾・閃光弾・分身による中断は既存の優先順位に従う。

## ブラウザ検証の範囲

`bench/pursuit-audit.cjs` は本編を開始し、実際の敵更新・衝突・経路・攻撃処理を進める。判定は到達だけでなく攻撃まで。敵の位置の履歴、復帰回数、経路コスト、除去、身体の交差と1フレームの移動量も保存する。本番への記録送信は無効。

- 旧市街: 170個の12m四方／高さ3mの区分を代表する歩行・上下移動、はしごの両方向、NAVのない実足場。計532ケース。
- 渓谷: 同じ基準の55区分、はしご、NAVのない足場。計131ケース。岩壁ポリゴンの外の地面はコース外として除外。
- 固定の回帰ケース: 旧市街32、渓谷1。停止を再現した26例、広域試験で見つけた初回選択の2例、以前の記録にあった西南の開始足場の上下・同高度3例、未入室の入口から屋外を追う1例、上段の梁から南の5m壁を追う1例。
- 旧市街の西南の開始足場 `(-29,4.4,-30)` は入門でも3方向から確認する。
- 既存の下降84ケース（旧市街15＋渓谷6 × 4難易度）、2体／8体の群れ × 4難易度も回す。
- 既存の高架50ケース、両マップのPC／タッチ・移動する標的、5m壁の14ケースと自然入力6ラン、建物入室と屋上の4構成も回す。

室内から追うケースでは、その敵が既に室内にいるという前提に合わせて、その建物への過去の人間の入室を再現する。未入室の部屋への立入禁止は別の単体・ブラウザ試験で確認する。

群れは先頭だけでなく全員の着地を確認する。8体は足場で順番待ち・着地点の再予約・難易度ごとの失敗回復を含むため、観察期限を30秒から60秒にした。ゲームの速度・待ち時間を変えるための数値変更ではない。各個体の着地時刻を結果JSONに残す。

復帰動作の交差ゼロは今回の掃引確認付きの登り・局所移動を対象とする。既存の標準乗り越え・落下アニメーションは別の集計欄に残している。

## 再実行

```sh
# 全域663経路。デフォルトはハード、各ケース45秒以内に攻撃まで確認
node bench/pursuit-audit.cjs
# CIでは停止の回帰33例
AUDIT_SET=recovery node bench/pursuit-audit.cjs
# 公開先のファイルで同じ判定
AUDIT_PUBLIC=1 AUDIT_SET=recovery node bench/pursuit-audit.cjs
# 入門・特定ケースなどの追加確認
AUDIT_DIFFICULTY=intro AUDIT_FIXTURE_FILE=path/to/fixtures.json node bench/pursuit-audit.cjs
node bench/zombie-descent-browser.cjs
node bench/gantry-pursuit-browser.cjs
node bench/zombie-routing-browser.cjs
node bench/zombie-wall-approach-browser.cjs
node bench/indoor-access-browser.cjs
```

`AUDIT_OUT` は結果の保存先、`AUDIT_DETAIL=1` は実地形を描画した各ケースの画像を保存する。Chrome実行パスは `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` で指定できる。

単体は影響するワークフローのコマンドを実行。重みつきDijkstra、低い天井の下の歩行、足の部分接地と空隙、接地判定の瞬断、入室境界、到達中の攻撃、初回の経路選択を追加確認する。

## 結果と限界

ローカルの最終公開候補で次を確認した。

| 検証 | 結果 |
| --- | --- |
| 広域代表経路 | 旧市街532/532、渓谷131/131が45秒以内に攻撃。今回の復帰動作の地形交差0、1フレーム1m以上の移動0 |
| 固定回帰 | 旧市街32/32、渓谷1/1が攻撃 |
| 西南の開始足場・入門 | 下・同高度・上の3/3が攻撃 |
| 下降・全難易度 | 84/84が攻撃、復帰動作の地形交差0 |
| 群れ | 2体・8体 × 4難易度、全員着地。8体の最終着地は入門34.18秒、イージー38.52秒、ノーマル19.93秒、ハード27.40秒 |
| 高架の追跡 | ノーマル25/25、ハード25/25通過 |
| 移動標的・入力 | 両マップPC/タッチ4構成、壁14例と自然入力6ラン通過 |
| 建物入室 | 両マップPC/タッチ4構成通過。未入室の入口から屋外の標的にも12.98秒で到達 |
| 影響ワークフローの単体 | 27コマンド通過（混雑待ちの探索上限を含む） |

公開容量は17.34MB。20MB目安の87%、50MB上限の35%。

初回CIでは自然スポーンの壁追跡で、1体が混雑した登り口の代わりを全域探索し続け、他の敵の探索を待たせる例を検出した。地形上は登れるが身体が塞いでいる候補も保持して192候補で探索を解放する。身体の重なりを許可せず、開始時の占有確認は維持する。追加の単体は修正前のコミットでは失敗し、修正後は通過する。ソフトウェア描画で同じ自然追跡も再確認する。

最初の公開後の663経路確認では、662例が45秒以内に到達したが、上段の梁から南の5m壁を追う1例は83.60秒かかった。上段で開始した候補リストが、地上へ移った後も残っていたため。探索開始時の高さを保持し、足場の高さが変わった場合・別の移動を始めた場合・敵がワールドから除かれた場合は探索を破棄する。これも修正前で失敗する単体と、固定回帰に追加した。

専用CIでは、下へ降りられるのに、経路場の予測コストが小さい同じ屋根上の横跳びを繰り返すケースも検出した。下にいる標的に対して、実際に身体が通って着地できる下降案がある場合は、それを優先する。下降がない場合の横跳びは残す。楽観的な経路場でも横跳びに負けないことを単体で確認する。

CIと公開先の最終結果は反映後に追記する。

全経路の全組み合わせ・全移動パターンを網羅した保証ではない。タッチ構成はブラウザの再現であり、物理iPhoneでの操作感とFPSは未検証。
