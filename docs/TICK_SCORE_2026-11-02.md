# 生存点の「30秒ごと加算」（2026-11-02）

生存点を、1秒ごとに滑らかに増える表示から、30秒ごとにまとめて入る表示へ変更。節目ごとに「+3,960」のバッジが出るため、達成感を得やすい。

## 得点

- 30秒ごとの加点：`floor(30 × 120 × 難易度倍率)`。イージー3,600、ノーマル3,960、ハード4,320。
- 120秒完走時は4回で、従来と同じ14,400 / 15,840 / 17,280点。合計・ランキング・ルールID（`corridor-time-score-v11`）・得点オブジェクト（`time-survival-v1`）は変更なし。Workerの検算も変更なし。
- 30秒の途中で終わった場合、まだ入っていない端数は終了時に精算する（`floor(経過秒 × 120 × 倍率)` と一致）。端数は最大でも1回分未満。
- `evaluate` が返す追加項目：`interval`（30）、`ticks`（払い出し済み回数）、`tickPoints`、`ticked`（払い出し済みの生存点）、`remainder`（端数）、`live`（HUD用：払い出し済み＋ダメージ＋撃破）。`total = live + remainder`。

## 演出

- HUDの合計は払い出し済みの点（`live`）。節目で約0.4秒かけてカウントアップし、合計と残り時間が一瞬拡大する。
- 節目のバッジ：既存の時計メダルと「+3,960 / 30秒生存」を合計スコアの下に約1.2秒表示。30秒間隔のため、30・60・90秒の各回が金色の大きいバッジ（約1.8秒表示）。5秒などの短い間隔にしても、30秒の境目だけ大きく出る作りにしてある。
- 残り時間の下に、次の加算までの進捗バー。加算の瞬間に空に戻る。
- 効果音は既存のMilestone.wavを再生（短い間隔にした場合の通常の節目はMedal.wav）。新しい素材は追加していない。
- 動きを減らす設定では、拡大・移動・カウントアップなしのフェード表示のみ。
- 一時停止中・背景では進まない。時計の飛び越し（読み込み直後など）は、演出を出さずに静かに合わせる。
- 結果画面とポーズ画面の生存点は、`30秒ごと N回 × 3960点 ＋ 端数 M点` の内訳で表示。ルール説明は日英とも更新。

## 確認

- `bench/survival-score.test.cjs`：全難易度・境界時刻で `ticked + remainder = survival`、`live + remainder = total`、端数は1回分未満（最大で約3,600点分が終了時にまとめて入る）。
- `bench/survival-tick-browser.cjs`：両マップ×3条件（PC・日本語、スマホ・英語、PC・動きを減らす設定）で、30秒前は表示なし、30秒でバッジと+3,960、終了時の端数精算、結果の内訳、再挑戦での初期化を確認。外部POSTは0。
- 既存の `survival-score-browser.cjs` と `combat-feedback-browser.cjs` は、今回の確認環境ではレンダラーが落ちて最後まで完走できなかった（スクリーンショットの時点。変更前のコードでも同じ環境で撮影が止まることを確認）。HUDの合計・表示式の検証箇所までは通過。
- 人間の通しプレイ、実機スマホでの見え方・効果音の聞こえ方は未確認。
