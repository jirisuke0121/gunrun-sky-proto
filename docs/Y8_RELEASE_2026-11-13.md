## Runtime and identity

The standard Pages entry stays platform-neutral. `python3 tools/make_release_zip.py --y8 output.zip` injects the platform flag and Y8 CDN script into the packaged entry. The package excludes the white-box canyon, editors, owner/admin pages, development tools and server source. Development mode, the trial difficulty and unfinished guided-course entry are hidden in the Y8 interface; Credits remains available.

`y8-runtime.js` initializes the SDK once, including both identifiers and the early-loaded SDK fallback. Guest play remains available when the SDK or login is unavailable. Login is called directly inside the click handler. A Y8 access token is sent only to `/auth/y8`; the Worker retrieves the profile from `https://account.y8.com/api/profile`, checks `client_id`, and derives a stable game-specific player ID from the verified `pid`.

The Worker returns a random 12-hour game session. Only its SHA-256 hash is stored in `y8_sessions`; neither Y8 access/refresh tokens nor email are stored. Browser session tokens remain in memory. Session renewal retries once after a Y8 401. A generation guard ignores late responses from an earlier account. Run ownership is fixed at the start of a run; queued records from a different signed-in account remain pending until the original account signs in. Reserved `y8_` IDs require the matching valid game session on every upload, including JSON values that could otherwise coerce to that prefix. Existing guest IDs and record idempotency remain intact. A valid chosen nickname is retained; otherwise the verified Y8 nickname is normalized to the existing public-name rule.

## Ads, focus and audio

Advertisements are requested only from Start, Retry or Restart actions. Load, menus, tutorial entry and automatic result transitions request none. Only `beforeAd` pauses/mutes; skipped, blocked or rejected ads let the action proceed. A provider that never starts has an eight-second fallback; once an ad starts, its lifecycle owns the pause. Duplicate clicks share one request.

Window blur, page hide and document visibility loss pause the chase and suspend the existing audio context. Returning leaves the player on the pause screen. Resuming restores the same graph and the player's volume/mute settings. Audio recovery respects the platform mute guard.

## Deployment order

1. Apply `server/y8-schema.sql` to the existing D1 database (additive and idempotent).
2. Deploy the Worker. `GET /` must report `y8Auth:1` and the unchanged ranked rules. Y8 origins are already present in `server/wrangler.toml`.
3. Publish the client and produce the `--y8` ZIP.
4. Upload the ZIP, select a fixed 16:9 landscape play area, and upload all required media slots.
5. Verify real Y8 auto-login, record attribution and QA on the uploaded preview before requesting review. Publication remains subject to Y8 review.

## Validation

- `node bench/y8-auth.test.cjs`: correct app, invalid tokens, upstream failure, stable identity, hashing, expiry, different accounts, array coercion, guest uploads and duplicate retries.
- `node bench/y8-package.test.cjs`: root entry, SDK, isolated platform config, included dependencies, credits, excluded private/development files and size.
- `Y8_BUILD_DIR=<extracted ZIP> node bench/y8-browser.cjs`: actual package with controlled SDK fixtures; shown/skipped/rejected/blocked ads, real audio-context suspension, focus/resume, original volume, 667×375 layout, no tutorial ad, mid-run account change and stale auth responses.
- Existing foundation, record integrity, shared score, ranked ghost, origin and audio tests; foundation and audio browser checks cover both maps and desktop/touch input.

SDK fixtures prove application behavior, not live Y8 identity/advertising availability. Physical iPhone listening/play-feel remains unverified.
