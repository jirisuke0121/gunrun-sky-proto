# はしごへの集中と登り経路の停止を改善（2026-11-06）

## 原因と変更

- はしごの経路コストは、7m の例で `7 + 7 / 1.1 = 13.36`。壁登り側の所要時間との比較では約2.2秒相当に扱われ、実際の約7.16秒（つかまり0.3秒、登り7/1.1秒、出口0.5秒）より有利だった。`zombie-ladders.js` で実際の動作時間を共通の経路コスト尺度（秒×6）へ換算し、はしご待ちの時間も壁登りとの比較へ加える。
- 旧処理は複数の敵が同時に同じはしごへ入り、入口・途中・出口の身体を無視して位置を更新していた。新処理は入口の順番と待つ足場、登る身体の間隔、出口の空きを確認する。通常の歩行へ同じはしごの待機位置を返すため、入口の一点へ全員を押し込まない。
- 出口の標準ノードが塞がれている場合、隣の実在する足場へ身体が通れることを確認して降りる。出口へ移る途中に塞がれた場合も、既に足が支持されていれば通常歩行へ戻す。空中の仮の足場や瞬間移動は追加しない。
- 登りの全区間を実際の身体で掃引し、地形・天井・閉じた室内の侵入規則を確認する。足元が傾斜したはしごでは現在の支持高さを保ち、設定上の下端へ地面を突き抜けて引き下げない。地形として通れないはしごは選ばず、段差・壁登り・跳び移り・迂回へ進む。
- 回帰試験で、距離と経路コストの改善を交互に判定して双方の基準を上書きし、同じ周回を進捗扱いする問題も発見。最良距離と最良コストをそれぞれ保持し、4秒の停止回復が先延ばしされないようにした。
- プレイヤーとの水平距離が3m未満だと停止検出から除外していたため、壁を挟んで近い地点でも押し続ける問題を発見。身体が通る直接経路がない場合は距離だけで除外せず、既存の停止検出と20秒の経路閉鎖で実際の開口へ回り込む。通常の近接攻撃・扉破壊・意図したはしご待ちは維持する。

通常の登り1.1m/s、ストーカー2.5m/s、壁登り0.8m/s、歩行・ジャンプ・難易度の数値は変更しない。被弾の押し出し、閃光弾、死亡・削除、練習の経路、同じはしご上での元の攻撃関数を維持する。扉や室内許可が変われば、はしご検証と経路場のキャッシュも更新する。

## 再現と検証方法

修正前は `2540a35` を固定して配信し、旧市街L0の同じ8体を比較した。全員が0.35秒以内にはしごを開始し、4秒までの計測で登っている身体同士の重なりが12,294件あった（組ごと・フレームごとの検出数）。修正後は同じ区間で0件。単独で空いたはしごを使う動作は残す。

`bench/zombie-ascent-browser.cjs` は旧市街10本・渓谷3本の実際のはしごを全件列挙する。各はしごで単独、8体、入口を12秒塞ぐ、出口を12秒塞ぐ4配置を試す。入門・簡単・普通・ハードの計208ケース。入門と普通はタッチ画面。全員が支持された上側の足場へ到達すること、登る身体同士の重なり・地形へのめり込みが0、1フレーム1m以上の移動がないこと、混雑時に実行可能な壁登りも選ぶことを検証する。実行不能な配置をスキップして成功扱いしない。

群れの通過試験では到達済みの敵を計測領域から取り除き、次の敵が出口から出られる状態を作る。狭いバルコニーに8体を永久に静止させて全員が同じ場所へ入ることは要求しない。入口・出口の妨害役は12秒まで保持する。固定した身体が出口を塞ぐ狭い足場で、重ならず待機し、解放後に再開する規則は単体でも検証する。既に上側の室内にいる妨害役は、それ以前の正当なプレイヤー入室を再現してから置く。

```sh
node bench/zombie-ladders.test.cjs
node bench/zombie-pursuit-stall.test.cjs
node bench/zombie-climb-progress.test.cjs
node bench/zombie-climb-queue.test.cjs
node bench/zombie-routing.test.cjs
ASCENT_LEVELS=intro,easy,normal,hard node bench/zombie-ascent-browser.cjs
node bench/pursuit-audit.cjs
AUDIT_SET=recovery node bench/pursuit-audit.cjs
node bench/zombie-descent-browser.cjs
node bench/zombie-wall-approach-browser.cjs
node bench/zombie-routing-browser.cjs
node bench/gantry-pursuit-browser.cjs
node bench/pc-controls-browser.cjs
node bench/indoor-access-browser.cjs
python3 size_check.sh
```

Chromeの実行ファイルは `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` で指定する。ローカルのゲーム配信と外部記録APIのスタブを用い、本番ランキングへテスト結果を送らない。公開確認は `ASCENT_PUBLIC=1` / `AUDIT_PUBLIC=1` / `DESCENT_PUBLIC=1` で同じ試験を公開アセットへ向ける。iPhone実機の操作感はブラウザのタッチ画面試験とは別の未検証範囲。

新たに発見した `region-0:-1:2--1` と `region--3:0:3--1` を `bench/pursuit-recovery-fixtures.json` に追加。固定再現は33から35件へ増やし、既存の `region-2:-1:0--1` も再確認する。CIのNav watchには、はしごの単体・全13本の52配置・周回判定の回帰を追加した。
