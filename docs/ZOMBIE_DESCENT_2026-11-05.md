# 屋上から下のプレイヤーへの追跡修正（2026-11-05）

対象は写真の中央建物北側バルコニー。プレイヤー `[1.3..11.5,4,-15.5]`、ゾンビ `[-8..-1,8,-13.5]` を実際の地形に置いて確認した。

## 原因と変更

下降リンクがない屋上では経路距離が Infinity となり、プレイヤー方向への通常歩行と崖落ち防止が競合して長時間縁で足踏みする。また、プレイヤーが NAV ノードのない階段・小足場へ降りると、以前の屋上を目標にした経路場が残る場合があった。

`zombie-descent.js` に局所的な下降救済を追加。通常の有効な経路や壁登り用の到達点を優先し、経路がない／進めない場合だけ実地形から下降案を探す。縁までの移動に連続した床があること、既存の短いジャンプ距離内であること、全飛行軌道に身体が通ること、着地点に実在する支持面と追跡の続きがあることを確認する。共有 NAV や地形は変更していない。

被弾、閃光弾、分身、死亡、着地点消失で中断。武器側が設定したノックバック速度は保持する。複数体は互いの身体へ食い込む移動を待機する。自発的な下降は既存の落下ダメージ免除を維持する。

小足場に対応する際、NAV ノードがなくても既存の壁登り用の到達点が有効なら、その経路を古い目標と混同しない。塔→5m壁の回帰ケースでも確認した。

## 検証

- `node bench/zombie-descent.test.cjs`: 床ノードなし、狭い台、壁・空中の接近経路・接続のない着地点の拒否、接近中／飛行中の中断、ノックバック保持、混雑待ち、有効な登り経路の保持。
- `node bench/zombie-descent-browser.cjs`: 旧市街15ケース、渓谷6ケース × 入門／簡単／通常／ハード = 84ケース。各開始点は身体の空間と足元の支持を検査。全ケースで下降後に攻撃。新しい下降処理の地形貫通0、1フレーム1m以上の移動0。
- 追加で写真の屋上に2体／8体を置き、入門・ハードで全員の着地を確認。
- 追加で改善した場所: `[-22.5,6.7,1.25]` の階段と `[30.75,7.4,-12.15]` の細い台。旧コードでは45秒以内の攻撃なし、修正後はいずれも攻撃まで到達。
- `zombie-routing-browser.cjs`: 2マップ×PC／タッチの既存経路20ケースと移動追跡4ケースを通過。
- `zombie-wall-approach-browser.cjs`: 壁・塔14ケースと自然スポーン6ランを通過。
- `gantry-pursuit-browser.cjs`: 通常・ハードの浮遊足場50ケースを通過。
- `nav-watch-browser.cjs`: 診断用ページでは救済だけ意図的に無効化し、経路不成立のログ・バッジ・送信データを引き続き検証。救済の成功は上記の別テストで要求する。
- Running browser workflow の単体22コマンドも通過。

ブラウザのタッチ設定での検証であり、実機iPhoneの操作感・FPSの測定ではない。マップ上の全地点の到達可能性を証明するものではない。

ローカル証拠は `browser-evidence/descent/`（全難易度結果、写真の建物の前後画像）と `browser-evidence/descent-crowd/`。これらの生成物は公開パッケージへ入れない。

容量: `python3 size_check.sh` で17.33MB、50MB目安の35%、20MB目安の87%。
