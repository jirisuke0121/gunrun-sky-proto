# ゾンビの落下・登りの上限撤廃と、撃ち落としの落下ダメージ

## 方針（本人の決定）

- ゾンビは落ちる・登るを「どこでも」できてよい。上限は外す。
- その代わり、**撃ち落とされて落ちた**ゾンビは高さに応じてダメージを受ける。高台の価値は「登ってくる所を撃ち落とす」で保つ。
- ゾンビが**自分で飛び降りる／降りる**場合はダメージなし。
- 登りは高さに比例した時間がかかり、登っている間は攻撃できない。

## 変更

| 項目 | 変更前 | 変更後 |
| --- | --- | --- |
| 降下リンクの落差（`zombie-routing.js` の `drop`／NAV生成） | 8 m まで利用（生成は 16 m まで） | 64 m まで（実質無制限） |
| 降下リンクの水平距離（`dropAcross`） | 2.5 m | 3.2 m（NAV生成の上限そのもの） |
| 柱・壁の登攀を探す範囲（`zombie-climb.js` の `planRadius`） | 半径 6 m（4秒停滞後は全域） | 半径 40 m。歩くより 0.75 秒以上速い、または歩いて届かないなら即登る |
| 落下ダメージ（新規 `zombie-fall.js`） | なし | 撃ち落とし時のみ。1.5 m まで 0、4.5 m 以上で満タン体力を失う（その間は直線） |

変えていないもの：跳び移り（水平3.2 m・高低差0.8 m。人間と同じ動きの原則）、登りの速さ（登攀 0.8 m/s、乗り越え 0.65 m/s ＝ 高さに比例した時間）、登攀中の攻撃不可（登攀中は `atkT` を0にして通常更新を行わない）。西地区の元の長い跳び移り・降下の許可。

## 落下ダメージの仕様

- 対象：地上から離れた最初のフレームで、気絶中（`stun > 0`）または 0.8 秒以内に被弾していたゾンビ。ジャンプ・降下・ハシゴ・登攀・出現などの動作中（`act` / `rise` / `fall`）に自力で降りる分と、ストーカーは対象外。
- 動作中に被弾して動作が打ち切られ、そのまま落ちた場合は対象（空中や壁の途中で撃ち落とす）。
- ダメージ＝満タン体力 × clamp((落差 − 1.5) / 3, 0, 1)。難易度ごとの体力に比例する（体力8なら3 mで4、4.5 mで即死）。
- 既存の `hurt()` を使うので、実ダメージ×2点のスコア、被弾の反応、体力0での撃破がそのまま働く。着地スタンは 0.45 秒＋0.12 秒/m（最大 1.2 秒）。
- 調整値は `zombie-fall.js` の `FALL`（`free` / `lethal` / `grace` / `stun`）。

## 確認

- `bench/zombie-fall.test.cjs`（新規）：ダメージ曲線、自力降下・動作中・ストーカーの除外、直前の被弾、難易度比例。既存の `bench/*.test.cjs` 全て通過。
- 実ゲーム（両マップ・デスクトップ）で開けた地面から落とした結果：自然落下6 m＝0、撃ち落とし 1 m＝0 ／ 3 m＝体力8→4 ／ 4.5 m・6 m＝撃破、被弾直後の4 m＝8→1.33。エラーなし。
- `bench/zombie-routing-browser.cjs`（旧市街・渓谷×PC・タッチ、各5地点）：全て攻撃到達、地形貫通0、座標の飛びなし。11/2午前の記録と比べて、旧市街の「塔→写真の壁」は攻撃到達 28.1→14.3 秒、移動距離 78.2→46.4 m。他の地点は同等（旧市街の写真の壁 8.9→9.2 秒、渓谷の上層→地上 2.97→2.6 秒）。
- 画像のスクリーンショット取得はこの環境のソフトウェア描画では時間切れになるため、その手順だけ省いて実行した。iPhone実機・実機FPSは未確認。
