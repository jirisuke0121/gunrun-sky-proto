# 近道を使う追跡と移動範囲の拡張

## 要件と実装

ユーザー指定は「歩行・段差登り・登攀・降下の近道」と「短い隙間の跳び移り」。到達時間と実際の移動距離を計測し、追跡が遠回りになる箇所を改善する。

- 近距離でも、足元が連続していなければ通常の経路選択を続ける。旧処理は3.2m以内で直進へ切り替わり、3mの隙間の縁で止まっていた。
- 両マップで、体の軌道と着地点を検査できた短い跳び移りを通常経路の候補にする。追加するリンクの上限は水平3.2m・高低差0.8m。通常の高い降下は水平2.5m・落差8mまで。西地区に元々ある長い跳び移りの許可は維持する。
- 検査と実行で同じ軌道式を使い、発進前と飛行中に体の通過を検査する。着地先の消失、被弾、閃光で中断して通常の重力へ戻す。未進入の屋内への侵入制限も維持する。
- 地面が連続する平坦な区間は、通常経路の先の点まで見通して細かな折れ曲がりを減らす。壁・空白・段差を跨ぐ省略はしない。
- 回り込みが現在位置への経路を大きく遠回りさせる場合は通常追跡へ戻す。移動中の目標更新、分身の誘導は維持する。
- 歩くより早い登攀が見つかれば、4秒停滞する前に選ぶ。接近・登る動作・乗り越え・その後の追跡の所要時間を比較する。局所候補は半径6m、192候補、フレーム当たり12候補・約2msの既存予算で調べる。通常経路が停滞した場合の復旧も残す。
- ホームの説明と英訳を、短い跳び移りも使う現在の能力に合わせた。地形の隙間やプレイヤーの操作・移動能力は変更していない。

主なコードは `zombie-routing.js`、`zombie-climb.js`、両HTMLの経路処理と `enhancements.js`。柱を共有NAVへ追加しない。

## 確認

- 両マップの10地点×PC/タッチ＝20条件で、追加後は全て到達。新しい跳び移り・降下中の地形侵入0、座標の飛びなし。
- 移動・2回の方向転換をするプレイヤーに3体が追従する4条件でも攻撃到達を確認。
- 写真の壁の既存6経路×PC/タッチも到達。通常出現のハード各3回は約26.1〜26.6秒でライフ0。難易度全体の評価ではない。
- 両マップの既存追跡・分身・閃光チェックが通過。
- パルクールの進入・解放各30条件×PC/タッチ、落下後の復帰、各3種の追手の再接近が通過。旧チェックの「dropアクションを必ず使う」は「dropまたはjumpdownで実際に下降し、体が地形を貫通しない」へ変更した。到達・逃走時間・被弾条件は維持している。
- 薄い壁・天井・足場なし・移動限界・屋内制限・被弾・閃光・着地点消失・回り込みの上限を単体確認。既存の床選択、NAV更新、降下開始、屋内制限、写真ルート確認と全インラインJS構文も通過。
- 短い跳び移りを実描画の連続画像でも確認した。

`bench/zombie-routing-browser.cjs` を既存CIへ追加。通常実行は現行コードを検証し、`ROUTING_COMPARE=1` は基準コードとの前後比較も保存する。保存先は `ROUTING_QA_OUT` で指定できる。

最短性の範囲は通常NAVと検査した局所候補内。全地形・全動作の総当たり、iPhone実機、実機FPS改善の計測は未実施。公開状況は対応PRとGitHub Pagesのデプロイ結果で確認する。
