# 管理画面（地図・詰まり・プレイヤー）

プレイ記録を見る場所を1枚に集めた画面です。GitHub Pages：`https://jirisuke0121.github.io/gunrun-sky-proto/tools/admin/`（旧 `tools/heatmap/heatmap.html` はここへ転送）。**ゲーム本体・Worker・DBの変更はありません**（既存のAPIを `ADMIN_TOKEN` で読むだけ）。

| タブ | 中身 | 読むAPI |
|---|---|---|
| 地図 | 被弾（橙）・落下（青）・死亡（赤）・**詰まり（紫）** を、マップを上から見た図に重ねる。マップ・難易度・高さ・時間帯で絞り込み、多い場所TOP6、点のクリックで詳細 | `GET /runs?full=1&limit=N` |
| 詰まり | ゾンビが接地中のプレイヤーより高い所で止まった記録の一覧。原因（`cause`）ごとの件数ボタンで絞り込み。行をクリックすると地図の該当点へ | 同上（`diagnostics.stuck`） |
| プレイヤー | 匿名IDごとの一覧（最終・プレイ・完走・途中終了・再挑戦・利用日数）。名前／ID検索、期間、完走の有無、配信元で絞り込み。行をクリックでそのプレイヤーの保存済みプレイと行動の履歴 | `GET /admin/players`、`GET /admin/player` |
| リプレイ・概要 | リプレイ再生・概要・動作診断は今はSitesの管理画面（リンクあり）。Workerの状態（ビルド・記録の版・ランキングの版）も見られる | `GET /`（認証不要） |

## 使い方

1. 上の `ADMIN_TOKEN` を入れる（そのタブの間だけ保存）。
2. 「サーバーから読み込む」で地図と詰まりのデータを取る（最新N件、既定200件。1プレイ約100KBあるので件数を増やすと重い）。プレイヤータブは自分の「読み込む」ボタン。
3. ネットに出さずに見るときは、記録の配列を保存して「JSONを開く」。データ入りの単独HTML：`node tools/admin/build-standalone.cjs 記録.json 出力.html`（記録は公開リポジトリに入れない）。

## 詰まりの `cause`

| cause | 意味 |
|---|---|
| `player-no-node` | 立っている床にナビ用のノードがない。ゾンビの目標が直前の屋上などのまま残り、全員そこで止まる |
| `target-off-floor` | ゾンビの目標ノードが、プレイヤーの立つ高さと違う |
| `zombie-no-node` | 止まったゾンビの足元にナビ用のノードがない |
| `no-route` | ゾンビの位置から目標まで、ナビ上の経路がつながっていない |
| `route-exists` | 経路はあるのに動かない。通行止め・渋滞・押し合いを疑う |

地図の紫の点は、詰まったゾンビの位置ではなく、そのとき**プレイヤーが立っていた位置**。「この床に立つと詰まる」を見るため。ゾンビの位置・ノード・距離場の値は点の詳細に出る。

## マップ形状の更新

マップを変えたら `node tools/admin/export-map.cjs`（playwright が必要）で `maps.json`（当たり判定の箱）を作り直す。

## 注意

- 記録の `build` が `-dev` で終わるものと、入門モード(`intro`)は除外。
- `mistakes` は1プレイにつきライフを失った回数分だけ入る。ライフを失わない接触は入らない。`diagnostics.stuck` は記録の送信がオンのプレイだけ。
- 件数が少ないうちは1人のプレイが大きく効く。「何プレイ」の数も一緒に見ること。
- 認証は今は `ADMIN_TOKEN` の手入力。Cloudflare Access などに移すときは、この画面の `api()`（1か所）だけを差し替える。
- 今は地図用に `/runs?full=1` で生の記録ごと読む。将来は Worker に「位置だけ返す管理用API」を足すと数十KBで済む（Worker側の変更になるので、Worker→Pagesの順で公開）。
